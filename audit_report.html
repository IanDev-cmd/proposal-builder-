1. Executive Summary

The stack is commercially viable and already has a few strong invariants (typed finance math, gold-scenario parity, PDF layout gates). System risk is concentrated in string-coupled pipelines: Cost Mother labels, regex prefill, n8n Code nodes, and unvalidated JSON at every hop. There is no runtime schema layer (no Zod, no Pydantic).

What is objectively sound

  • quoteFinance.ts documents contingency 2.25%, VAT 20%, staff buffer +3h, min 4 billable hours as named constants.
  • financialParity.ts blocks approval on > £0.02 gold-scenario drift.
  • sapphireLead.ts is a canonical n8n alias registry — the right pattern for the rest of the stack.
  • Bundled PDF engine raises ProfileValidationError → HTTP 422 on cover geometry failure.
  • n8n Transform is explicitly pass-through for money (UI is the finance source of truth).

What is subjectively fragile

  • Prefill is a keyword/regex engine (leadPrefill.ts) with REP-name lists and scored note chunks.
  • Catalogue labels must match across TS, GAS, n8n, and the sheet — including the preserved typo All Sesons.
  • sheetsWrite toasts and continues; PDF and Sheets can diverge (split-brain).
  • Production engine app.py still does except Exception: pass on profile warm-up and has no inbound schema.
  • Four systems can disagree on a quote: UI calc, sheet columns, gold fixtures, PDF render.

Target agentic architecture — background repair loop

Step-by-step rollout (no user interruption)

  1. Phase 0 — Observe only (week 1). Introduce a FailureEvent bus in the UI (postWebhook, LeadDataFetch, generate) and in the engine (validation 422, warm-up, missing insert). Log to an existing sheet tab or n8n Data Store. Zero behaviour change.
  2. Phase 1 — Contract gates (week 2–3). Zod at postWebhook / lead fetch / CostRatesFetch. Pydantic on production /generate. Malformed JSON stops being { ok: true }. Health endpoint reports warm-up errors.
  3. Phase 2 — Safe retries (week 4). Outbox for Sheets writes. Idempotent QuoteStatus. Background loop retries network/5xx only. UI toasts “syncing…” instead of “failed, continuing anyway”.
  4. Phase 3 — Label drift agent (week 5–6). Compare live _Nexus Catalog labels to QUOTE_LINES + aliases. Flag “Sesons”, 2CSD mismatch, unknown rates for the selected vessel key. Propose catalogue patches; do not auto-merge money.
  5. Phase 4 — Prefill confidence (week 7–8). Per-field confidence. Low-confidence fields stay blue until REP confirm. Confirmed corrections feed alias tables (objective), not new one-off regexes (subjective).
  6. Phase 5 — PDF self-check (week 9+). Promote bundled profile_validation.py to production. Golden profiles in CI. Agent invalidates measure cache on template mtime. Overflow warnings already in X-Warnings become first-class FailureEvents.

Observability & schema-drift detection

  1. RED for webhooks: rate, errors, duration on LeadDataFetch, CostRatesFetch, QuoteBuilder, NoteAppend, QuoteStatus.
  2. Drift counters: unknown catalogue labels/day, rate-key fallbacks used, prefill corrections/day, gold-parity mismatches, PDF 422s by template id.
  3. Split-brain gauge: quotes where PDF status=ready but sheet status≠ready (outbox lag).
  4. Scheduled gold verify: verifyAllGoldFinancials() against live Cost Mother; open an issue when bundled snapshot diverges.
  5. Policy: agents may coerce types, retry I/O, map aliases, and pick nearest insert. Agents may not change VAT, margin, contingency, or grand total without REP confirmation.

Highest-leverage first move: make success honest (stop { ok: true } on empty JSON; stop swallowing warm-up; stop generating PDFs while QuoteStatus is best-effort). That alone turns today’s silent split-brain into a healable outbox.
